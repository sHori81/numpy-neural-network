## 原稿

### 導入（25秒）

課題1から3までの進み具合と、リファクタリングの方針、動作の確かめ方を説明します。
どの課題も「まず動くものを作ってコミット、見直してもう一度コミット」という手順で進めています。

リファクタリングでは Claude を使っていますが、書き換えをそのまま任せるのではなく、まずコードの問題点を挙げてもらっています。
そのうえで、1つずつネットで調べて本当に問題なのかを確かめ、納得したものだけを自分で直しています。

変更は「振る舞いを変えない構造の改善」と「計算結果が変わる改善」に分けて扱い、前者は前後で出力が完全に一致することを確かめています。

### 課題1（30秒）

課題1は、画像1枚を入力して、0〜9の1つを出力するプログラムです。

> 実演：`python report/src/kadai1_after.py`、100を入力 → 9

リファクタリングでは、変数名の変更やデバッグ用printの削除に加えて、画素値の正規化を行いました。
画像1000枚を前後のプログラムに入力して比べ、構造の変更だけの版は出力が完全に一致しました。
また、変更を1つずつ元に戻して比べることで、結果を変えたのは正規化だけだと特定しました。

### 課題2（30秒）

課題2は、ミニバッチを入力にして、クロスエントロピー誤差を計算するプログラムです。

> 実演：`python demo_kadai2.py` → 2.667…

読み込みとミニバッチの選択を別の関数に分け、順伝播を関数にまとめ、絶対パスを相対パスにしました。
乱数を使う順番を変えないようにリファクタリングし、同じシードで前後の誤差を比べました。log(0)対策の `eps` を0にすると、前後の値が全桁一致しました。

### 課題3（60秒）

課題3は、誤差逆伝播法による学習で、エポックごとの評価まで実装しました。

> 画面：`history.png`（50エポックの誤差と正解率のグラフ）

リファクタリングでは、`main` から初期化と1エポック分の学習を関数として取り出し、重みを辞書にまとめて引数を減らしました。
また課題2と同じく、`backward` がバッチサイズを引数で受け取らず、入力の形から求めるようにしました。

動作の担保として、シードをそろえて前後で2エポック学習させ、誤差と正解率が全桁一致することを確かめました。

一方、抜けていた画素値の正規化を入れたところ、学習率0.01では学習が遅くなり、テスト正解率は96.2%から91.6%に下がりました。
入力が小さくなり、1層目の勾配も小さくなるためと考えています。学習率を上げると改善したので、今後調整します。

### まとめ（10秒）

以上のように、挙げてもらった問題点を自分で調べて理解したうえで直し、変更前後の出力を比べて振る舞いを確かめながら、段階的にリファクタリングを進めています。

## 質問されたとき用のメモ（読み上げない）

### Claude の使い方（「AI に任せきりでは？」と聞かれたとき）

進め方：
1. Claude にコードの問題点を挙げてもらう（書き換えはまだ頼まない）
2. 挙がった問題点を1つずつネットで調べ、本当に問題か、なぜ問題かを確かめる
3. 納得したものだけを自分で直す。納得できないもの、今は不要なものは見送る
4. 直したら、前後の出力を比べて振る舞いが変わっていないか確かめる
5. 気づいたことは README.md にメモしている

説明できる例（※実際に調べた内容に合わせて直す）：
- 変数名 `var`：中身は分散ではなく標準偏差 → `std1`、`std2` に変更
- 重みの初期化を 1/√N にする理由：入力ノード数 N が多いほど出力の分散が大きくなるのを防ぐ（Xavier の初期化）
- `np.clip`：`np.exp` に大きな値を入れるとオーバーフローする
- ソフトマックスの `axis=-1, keepdims=True`：ミニバッチの行ごとに和をとるため
- `if __name__ == "__main__":`：import しただけで計算が走らないようにする
- 課題3の正規化：入れると学習が遅くなった → 入力が小さくなり勾配も小さくなるため、と調べて理解し、学習率を調整する方針にした


### 課題1（シード81、画像1〜1000）

| | 正解率 | シグモイドの飽和率 | 出力 |
|---|---|---|---|
| 前 | 9.2% | 95.5% | 9が721回、6が213回、ほか |
| 後 | 10.0% | 0.0% | ほぼ全部9（999/1000） |

- 学習前なので正解率は前後とも約10%（でたらめに選ぶのと同じ）
- 後でほぼ9しか出ないのは、正規化で中間層の出力がどの入力でも0.5付近になり、乱数の重みでもともと値が大きいクラス9が選ばれ続けるため

### 課題2

- シード0：前 2.4589035261042866、後 2.4589022144299957（差は約1e-6、`eps` の分）
- `eps=0` にすると前後が全桁一致

### 課題3

- 設定：中間層1000ノード、バッチサイズ100、学習率0.01、50エポック
- 50エポック後のテスト正解率：正規化なし（前）約96.2%（訓練は99.7%）、正規化あり（後）約91.6%
- 2エポックの比較（シード0）

| 版 | 1エポック目 誤差 / テスト正解率 | 2エポック目 誤差 / テスト正解率 |
|---|---|---|
| 前 | 0.6082 / 91.24% | 0.3120 / 92.77% |
| 後から正規化だけを外した版 | 0.6082 / 91.24%（全桁一致） | 0.3120 / 92.77%（全桁一致） |
| 後（正規化あり、学習率0.01） | 1.9103 / 77.25% | 1.2781 / 81.73% |
| 後（正規化あり、学習率0.1） | 0.9615 / 88.77% | 0.4019 / 89.35% |
| 後（正規化あり、学習率0.5） | 0.6962 / 91.56% | 0.2941 / 91.65% |

- 正規化なしは、訓練99.7%に対してテスト96.2%で、過学習ぎみ
- リファクタリングで変えた点の一覧
  - `init_params`（初期化）、`train_one_epoch`（1エポックの学習）を関数として抽出
  - パラメータと勾配を辞書にまとめ、更新を `for key in params` の1ループにした
  - `backward` のバッチサイズを `y_pred.shape[0]` から求めるようにした
  - `accuracy` を、入力からまとめて計算する形にし、`eval_chunk_size` 枚ずつ順伝播してメモリを節約
  - コメントアウトしていた `get_minibatch` を削除
  - `plot_history` 内の変数 `epochs` がグローバル変数と同じ名前だったので `epoch_axis` に変更
  - グラフを `history.png` に保存してから表示する
  - エポック番号の表示を1から始めるようにした（表示だけの変更）
